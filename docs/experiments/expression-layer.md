# 読める姿勢(ジェスチャー)層を、ドットグリッドのペットに適用する

moon で完走した spike([css-gesture.md](css-gesture.md))の設計則を、CSS を使えない
PC 版(wlr-layer-shell の常駐ウィンドウにドットグリッド)へ持ち込んだ作業の記録。
段階1 は**駆動源をペット自身の内部状態**(エネルギー・まとまり・テンポ・放置時間)にする。
決定モデルを挟まないのは、姿勢空間と描画そのものを先に検証するため(段階2 で
決定モデルを入力にするときは、ここで作った写像を分布に差し替えるだけになる)。

**確度の書き分け**: 「確認済み」= 実行して出力を見た、「たぶん」= 計算からそうなるはず、
「未検証」= 確かめていない。実測の欄はすべて実行したコマンドの出力の数値をそのまま写している。

## 設計の判断

### 判断1: 姿勢パラメータ空間は spike の `poses.json` をそのまま持ち込む

次元は `tilt_x / bob / rot_x / rot_y / rot_z / lift / sink / size / freq / flick`。
**角度(deg)は単位がそのまま使える。持ち込み直しが要るのは長さだけ**(pose unit → セル)。
そこで、長さの換算だけを新しい定数 `CELLS_PER_POSE_UNIT = 2.5` にした。
spike が 118px の枠に対して `px_per_unit = 18` だったのを、32セルの表示に写した値。

### 判断2: 「回転」は板の厚みの投影として描く(オルソ投影)

ドットグリッドでは立方体の面は描けない。spike で回転が読めた本質は
**「別の面が見える」という離散的な変化**だったので、同じ離散性を
**厚みのある板(スラブ)**で作る。板は厚み `SLAB_THICKNESS_CELLS` で、描くのは2つだけ。

- **前面** … 見えているセルを1回だけ描く
- **側面** … シルエットの**境界にあるセル**だけ、厚みのぶんだけ点を掃く

pitch を付けると上端の側面が輪郭の外へ帯として現れる(帯の高さ = 厚み × sin(pitch))。
yaw なら左右の縁に同じ帯が出る。roll は板ごと回るだけで帯は出ないが、小さい角度でも読める。

**層を何枚も重ねる作りは採らなかった。** 板を「見えているセルの層」として何枚も重ねると、
ずれた半透明の像が重なって「雲」になり、spike が実測で否定した混合の失敗
(不透明度の重ね合わせ)を描画の中で再現してしまう。見えるのは常に前面と側面だけで、
板の奥は隠れる。→ 最初に層方式で実装しかけて、この理由で捨てた(捨てコストは約40分)。

投影は**オルソ**(透視除算なし)にする。理由は2つ。

- **逆写像が解ける。** 描いたドットと、クリックした位置が食い違わない(`cell_at_posed`)
- **つまみが増えない。** CSS では `perspective` という距離のパラメータが要ったが、
  ここでは厚みだけで足りる。同じ効果を2つの量で作ると、しきい値の実測が濁る

### 判断3: 厚みは 3.5 セルにする(しきい値は実測で確かめる)

厚み `t` セル・pitch θ のとき、側面の帯の高さは `t·sin θ` セル。帯が
**ドット1個ぶん**になるときが「見え始め」、**2個ぶん**が「面として明確」。

`t = 3.5` とすると **θ = 16.6° / 34.8°**。spike が `perspective: 170px` で測った
**15° / 30°** とほぼ同じ数字になる。これは偶然合わせたのではなく、
「読める下限 = ドット1個ぶんの分離」という同じ条件を別の手段で満たしているため。

**ただしこれは予測であって実測ではない**(着手時点では未検証)。実際に自分の描画を
固定位相で止めて測り、その値を下の「結果」に使っている。

### 判断4: 状態 → 8ジェスチャーの重みは「駆動源ごとに1項」の加算スコアにする

決定論的で、どの状態がどの項を立てたかが1行で言えることを優先する(段階2 では、
ここが決定モデルの分布に置き換わる)。

| ジェスチャー | スコア | 意味 |
|---|---|---|
| `idle` | 0.45 | 基準。何も主張しない |
| `perk_up` | 1.10 · e · fresh | 元気で、最近かまってもらえた(身を起こす)|
| `nod` | 0.95 · e · c | 元気で、体がまとまっている(落ち着いた肯定)|
| `shake` | 1.15 · (1 − c) | 体がまとまらない(落ち着かない)|
| `lean_in` | 0.90 · fresh · (1 − c) | 最近かまってもらい、まだ整っていない(身を寄せる)|
| `recoil` | 1.20 · (1 − e) · slow | 弱っていて、がっかりもしている(退く)|
| `settle` | 1.05 · (1 − e) | 弱っている(沈む)|
| `flicker` | 1.60 · 4e(1−e) · (1 − c) | 元気が中間で、まとまっていない(迷い)|

- `e` = エネルギー(0〜1)、`c` = まとまり(0〜1)、`slow` = がっかりの度合い(テンポ 1.0→0.6 を 0→1)、
  `fresh` = 放置時間が短い度合い(90秒で 0 になる)
- 最後に合計 1 に正規化する。`flicker` の `4e(1−e)` は「元気が中間のときだけ 1」の山
- `flicker` だけ係数が 1.6 なのは、`shake` と同時に立つ項だから
  (元気が中間のときは迷いを主役にする)

**限界(着手前に明記)**: 実運用ではエネルギーは放置時間とほぼ同じ速さで減る(150秒)ため、
`e` と `fresh` は独立ではない。この2つが同時に立つ状況は少ない。独立に動かせるのは
**まとまり**(形の乱れ)と**テンポ**(学んだ生活リズムのがっかり)で、写像の検証もこの2軸を中心にする。

## 方法・条件

```sh
nix develop -c cargo run --release -- --probe-pose docs/experiments/expression-layer
```

- 表示は 384×384px・32×32セル(12px / セル)。実機のアプリと同じ。
- **位相を固定して測る。** 動いている絵では差が読めないことを spike が実測している
  (`docs/experiments/css-gesture.md`「アニメを 0% に凍結して測る」)。振れの山は位相 90 度。
- 「帯の高さ」は、横一列だけを点灯させた板を描き、**不透明画素を含む矩形の高さ**から
  姿勢なしの高さ(=ドットの直径)を引いて測る。予測(厚み×sin)と並べる。
- 「roll」は、横一列の両端の列の重心の高低差から、実際に描かれた角度を `atan` で戻して検算する。
- 画像は `docs/experiments/expression-layer/raw/` に出る(1枚440KBの無圧縮 PNG なので .gitignore 済み)。
  確認用の一覧画像は ImageMagick で作る(「道具」の節)。

## 結果

### 側面(帯)が読める下限 = pitch 15度(確認済み)

ドットの直径(姿勢なし) = 10px。

| pitch | 帯の予測 (厚み×sin) | 描画の高さ | 帯の実測 | 帯/ドット径 |
|---|---|---|---|---|
| 0度 | 0.0px | 10px | 0px | 0.00 |
| 5度 | 3.7px | 14px | 4px | 0.40 |
| 10度 | 7.3px | 18px | 8px | 0.80 |
| **15度** | 10.9px | 22px | **12px** | **1.20** |
| 20度 | 14.4px | 25px | 15px | 1.50 |
| 25度 | 17.7px | 29px | 19px | 1.90 |
| 30度 | 21.0px | 32px | 22px | 2.20 |
| 35度 | 24.1px | 35px | 25px | 2.50 |
| 40度 | 27.0px | 37px | 27px | 2.70 |
| 45度 | 29.7px | 40px | 30px | 3.00 |

**帯がドット1個ぶん以上になる最初の角度 = 15度。** 予測(16.6度)より 1.6度 低いのは、
丸いドットの縁のぼかし(1px)と画素への丸めのぶんと見ている(たぶん)。
**spike が CSS の `perspective: 170px` で測った 15度 と同じ値になった。**

→ **pitch 15度が「側面が見え始める」下限、30度(帯 = 2.2ドット径)が「面として明確」の下限。**
語彙の `nod` は 18度なので、うなずきとして確かに読める側に入っている。
`perk_up` の静的 tilt 70度 は帯が 3ドット径を超え、明確に「のけぞっている」側。

### roll(画面内の傾き)が読める下限 = 3度(確認済み)

体の縁までの距離 10セル = 120px、ドットの半径 4.9px。

| 0度 | 0.0px | 0.0度 | 0.0px | 0.00 |
| 1度 | 6.5px | 1.0度 | 2.1px | 0.43 |
| 2度 | 13.0px | 1.9度 | 4.2px | 0.85 |
| **3度** | 19.5px | 2.9度 | **6.3px** | **1.28** |
| 4度 | 25.9px | 3.9度 | 8.4px | 1.70 |
| 5度 | 33.5px | 5.0度 | 10.5px | 2.13 |
| 6度 | 40.1px | 6.0度 | 12.5px | 2.55 |

**縁がドット半径ぶん動く最初の角度 = 3度。** 「描かれた角度」の列が要求した角度と一致するので、

### 姿勢ゼロでは見た目が1ビットも変わらない(確認済み・テストで固定)

「ジェスチャー層を入れても、何も主張していないときは元の絵のまま」という不変条件を
テストで固定した(`a_zero_pose_draws_exactly_like_the_unposed_draw`。体・echo・色素を
すべて載せて画素まで比較)。`cell_size` も中心からの相対座標も整数なので、位置の計算は
元の式と厳密に一致する。原点に小数部がある場合と、サーフェスに余白がある場合も別のテストで確かめた。

### 機械の目視(未検証: 人による判定は未実施)

- pitch 系列の4枚(0度 / 15度 / 30度 / 45度)を並べた画像では、**0度=細い点線、
  15度=縦に伸び始めた線、30度=明確な帯、45度=最も厚い帯**と読めた。
  上の「15度で帯が1ドット径」という幾何の実測と一致する
- 本物の O2u に `perk_up` / `settle` / `shake` / `recoil` を固定した4枚は、
  大きさ・上下位置・傾きがそれぞれ違い、**4枚は区別できた**

**いずれもエージェント自身の画像認識による確認で、人の判定ではない。**
spike と同じく、最後は人が動いている絵を見て決める必要がある。

## 結論

- **CSS を使えなくても、姿勢の語彙と描画則は持ち込める。** 角度は単位が同じなので
  そのまま移り、写し直すのは長さの単位だけだった
- **回転を読ませる仕組みは「厚みのある板の側面」に置き換えられた。** CSS の
  `perspective` が担っていた役割を、セル単位の厚み(3.5セル)が担う。
  実測の下限は **pitch 15度**(帯 = ドット1個ぶん)、**roll 3度**(縁 = ドット半径ぶん)。
  spike が CSS で測った 15度 / 数度と一致した。**同じ「1ドットぶんの分離」という
  条件を別の手段で満たしているため**
- **しきい値は流用せず、自分の描画で測り直した。** 測る前に予測として 16.6度 / 4.1度を
  記録し、実測で 15度 / 3度 を得た(予測が当たったことも記録として残す)
- **オルソ投影にすると逆写像が解ける。** 姿勢で体が動いても、クリックした位置が
  見えているドットと一致する(`cell_at_posed`)。透視投影を選ぶと失われる性質で、
  ペットにとっては見た目より効く
- **状態 → 姿勢は、体の1つの曲線として読める。** 放置した O2u は
  `perk_up`(0秒)→ `nod`(30〜60秒)→ `settle`(90秒以降)と移り、
  エネルギー・まとまり・テンポの値と整合する
- **厚みと層の設計は、spike が否定した失敗を描画側で繰り返さないために効いている。**
  「見えているセルの層を重ねる」実装は雲を作るので、前面と側面だけを描く形にした

## 限界

- **人が読み分けられるかの判定は未実施。** 幾何の下限は実測したが、
  「`nod` と `perk_up` の区別がつくか」のような語彙どうしの混同しやすさは見ていない。
  エージェントの画像認識では4枚を区別できた、という弱い確認だけがある
- **`flicker`(迷い)は実運用ではほぼ立たない。** 出荷している体のまとまりが
  0.93〜1.00 に張り付くので、`(1 − c)` の項がほとんど 0 になる。
  この項が動くのは、粒子の体がはぐれた瞬間のような「本当に乱れたとき」だけ。
  段階2 で決定モデルの `uncertain` を入れる場所として空けてある
- **葛藤から出る roll の上限が未判定。** 「弱って、がっかりもしている」で 49.8度になる。
  spike の最大は 25.7度だった。大きく傾くことが「読める」のか「大げさ」なのかは人が決める
- **エネルギーと放置時間は独立でない。** 実運用では両方 150秒で尽きるので、
  写像の2つの入力が同時に動く。独立に動かせるのはまとまりとテンポだけ
- **まとまりを崩す操作が無い。** クリックでは Lenia の塊は崩れず、まとまりの値は
  0.99 のまま(上の表の「崩した後」がそれを示している)。粒子の体でのはぐれ以外に、
  この入力が下がる場面を作れていない
- **表示は 384×384px・12px/セル の1条件だけ。** M5Stack の 320×240(43×32 の場)では
  セルが小さくなるので、下限の角度が変わる可能性がある(未検証)
- **段階2(決定モデルを入力にする)は未着手。** ここで作った写像を分布に差し替える
- 波の形は正弦1種類のまま(spike のトレードオフをそのまま引き継いでいる)。
  `perk_up` の「沈んでから跳ねる」は表現できない

## 設計の追加判断(実装中に決めたもの)

- **`flick` は消えずに薄れる。** `visibility = 1 − flick × 0.7 × (1 − blink)`。
  1.0 にすると `flicker` 単独で不透明度が 0 になり、**消えている瞬間**ができる。
  体が完全に消えるのは「迷い」ではなく「不在」に見えるので、最小 0.3 倍に留めた
- **姿勢の位相を進める上限を 0.25 秒/フレームにした。** ウィンドウが隠れていた、
  デバッガで止めた、といった理由で描画の間が空くと姿勢だけが跳ぶ。位相は 0..2π に
  畳まれるので破綻はしないが、上限があると空いた後も動きが連続に見える
- **不透明度はいちばん濃いドットが勝つ合成にした。** 側面と前面が重なったときに
  不透明度が足し合わさると、板を厚くしただけで明るくなる = 姿勢ではない信号が出る。
  姿勢ゼロの同一性もこの合成が支えている
