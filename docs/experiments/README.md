# 実験の記録

ペット本体の設計を変えなかった実験を、テーマごとに残している。いまの設計と、その根拠になった判断は
[docs/DESIGN.md](../DESIGN.md) にあり、設計に効いた結論だけは docs/DESIGN.md「実験から分かったこと」
にも書いてある。

- 各節は、おおむね「問いと背景 → 方法・条件 → 結果 → 結論 → 限界」の順で書いてある。結論だけ知りたい
  ときは、下の表から読む
- 実験の道具は `crates/vmc-pet-body/examples/` にあり、各節に使ったツールの名前を書いてある
- コードのコメントは `docs/experiments/<ファイル>「節の名前」` の形で節を参照している

## [コントローラの自己調整学習(issue #3)](controller-learning.md)

| 節 | 問い | 結論 | 設計への影響 |
|---|---|---|---|
| コントローラのパラメータは報酬の候補を動かせるか | パラメータを変えると、総量・活動度・速さはどれだけ変わるか | 既定値の近く(±20%)では、世話と放置の差の 0〜6% しか動かない。世話と放置と同じだけ動かせるのは既定値の数倍以上に強く突く範囲だけで、そこでは崩壊が起きた | いまの行動の定数をホメオスタシス報酬で学習させても意味が薄い。進めるなら行動の種類を変えるのが先 |
| 粒子の体(1091)では、行動で報酬が変わるか | 崩れた 1091 を、手で書いた行動でまとめ直せるか | 場の全体に届く誘いで塊の重心へ引くと、3割を散らしたとき戻るまで 50.9 秒 → 3.7 秒、割れたまま 7/16 → 0/16。強いほど良くなるので、行動の代償といつ行動するかを報酬に入れる必要がある | なし。学習ループの実験の土台にできる |
| 代償を入れた報酬で、最良の行動は範囲の内側に来るか | 強さ・届く距離・しきい値の格子で、報酬が最大の組は範囲の端に張り付かないか | 吸い寄せの激しさと、崩れていないのに誘うことの2つを代償に入れると、最良の強さは 0.05〜0.1(内側)、しきい値 0.9〜0.95。崩れていないのに誘う代償が無いと「いつも誘う」が選ばれた | なし。進化戦略の実験に使える問題の形になった |
| 小さな学習ループを回す | その報酬で進化戦略を回すと、雑音があっても最良の組の近くへたどり着けるか | (3/3,10)-ES・30 世代で、3つの出発点すべてが格子の最良の近くへ収束し、学習に使っていない場面で格子の最良と見分けがつかない性能(差 ±0.003 以内)になった。最良のまわりは平らで、学んだ値は1点に決まらない | なし。問題はまだ格子で調べきれる大きさ |
| 状況(エネルギー)に応じて行動を変える学習 | エネルギーで最良の行動は変わるか。エネルギーに応じた行動を学べるか、定数の行動より良くなるか | 最良の強さは弱るほど下がるが、定数の行動との差は報酬で 0.01 ほど。報酬を「弱るほど吸い寄せを嫌う」にすると、弱るほど強さを下げる形(0.130 → 0.038)を学んだが、学習に使っていない場面での得は +0.005 ± 0.005 で雑音と区別できない | なし。状況で最良がはっきり変わる設定が要る |
| 体の状態(まとまり)に応じて誘いを強める学習 | まとまりを入力にした行動を学ばせると、一定の強さより良くなるか | 良くならなかった(−0.005 ± 0.002)。判断ごとの記録から、報酬の「吸い寄せの激しさ」は誘いの効果よりも、まとまった体のふだんの動きの揺らぎに左右されていると分かった | なし。代償の測り方を、誘っているあいだの速さの超過の和に直す必要がある。判断ごとの記録を残せるようにした |
| 代償の測り方を直す | 誘いが原因の速さだけを数える代償にすると、強さに応じて測れるか。その報酬で、状態に応じた行動を学ぶか | 誘っているあいだの、ふだんの揺らぎの上限を超えた速さの和は、何もしないと 0 で、強さ 0.1 から出はじめ 0.2 で大きくなった。報酬を和の形にすると、学習が戻りかけで弱める形を見つけた(戻りかけの超過 0.0117 → 0.0001)が、どの行動もほぼ最善に届き、報酬の合計の差は +0.000 ± 0.001 | なし。和の形の報酬を作った。状態に応じる得を測るには、もっと難しい場面が要る |
| ユーザー操作を含む記録をためる | 実際の触り方では、いまの報酬の中身はどれだけ動くか | 125 秒・クリック 10 回の記録では、まとまりが 0.9 を下回った秒が 0(最小 0.983)。実際の触り方は学習で使った崩し方よりずっと穏やかで、いまの報酬は動かない。ポインタを乗せている時間が 94% で、ホバーがそのまま誘いになっていた。クリック後 2 秒だけ速さの最大が 0.44 → 0.62 | なし。ホバーと誘いを切り離す必要がある |
| 実際の連打で学ばせ直す | 実際の崩れ方(連打で1割がはぐれる)に合わせると、学んだ行動は効くか | 効いた。はぐれた粒子がいた秒は 41 秒 → 1 秒、報酬の差は +0.197 ± 0.042。誘いはじめる目安は「はぐれた粒子1個以上」が最良で、いまのコントローラ(まとまり 0.9 未満)はほとんど働かない。実機の記録でも、崩れが 69〜76 秒から 1 秒になった | PC 版のコントローラを、はぐれ1個以上・強さ 0.13・距離 39 に変えた |

## [決定モデルの出力を CSS ジェスチャーにする](css-gesture.md)

| 節 | 問い | 結論 | 設計への影響 |
|---|---|---|---|
| 決定モデルはジェスチャーを選び分けられるか | テキストの状態を見て、8個のジェスチャーから意味の通るものを選べるか | **モデル次第。** Clef-Flash (9B) は8件が5種類に分かれ、energy/approach も意味の通る向きに出た。Laya (0.42B) は**8件すべてが同じ答え**で判別しなかった | なし(ペット本体には未接続)。小さいモデルを使う路線は、この用途では成立しない |
