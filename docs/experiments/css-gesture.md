# 決定モデルの出力を CSS アニメーションのジェスチャーにする

decision model（System One API）に「どのジェスチャーを・どの強さで」を選ばせ、
その出力を CSS アニメーションのパラメータに写して、言葉を使わずに反応させる試み。

## 問いと背景

vmc-pet の表現軸は 色(色素) / テンポ / 身じろぎ の3つしかなく、「生き残る関数で表情を足せるか」
「別の形から戻る帰り道はあるか」の2つの実験で、**質の違う見た目は作れるが一方通行で、表情には
使えない**ことが分かっている（[expression-axes.md](expression-axes.md)）。これは Lenia 場という
体に起因する制約で、場は「安定に作れて、かつ可逆に戻れる」範囲しか表現できない。

CSS の `transform` / `opacity` / `filter` にはこの制約が無い。本質的に可逆で、崩壊の概念が無い。
そこで、**体の代わりに「ジェスチャーの語彙」を持ち、決定モデルに選択させる**路線を試した。

決定モデルはテキストを生成しない（`output_modalities = ["decisions"]`、全応答で
`output_tokens = 0`、`/v1/chat/completions` は HTTP 500）。したがって:
**ジェスチャーの定義（CSS）は手書きで固定し、決定モデルには選択と強度だけを担わせる。**
生成は決定論的な写像が行う。

## 方法・条件

- 決定モデル: `ggml-org/Laya-GGUF` Q8_0（0.42B）と `ggml-org/Clef-Flash-GGUF` Q4_K_M（9.08B）
- 実行: moon の CPU、`llama.cpp b11539`（`~/.local/share/llama.cpp/llama-b11539/llama-server`）
- ジェスチャー語彙 **8個**（手書き、`gestures.css`）: `idle` / `perk_up` / `nod` / `shake` /
  `lean_in` / `recoil` / `settle` / `flicker`
- 質問4つを1リクエストで:
  - `gesture` = `choice`（8候補）— どのジェスチャーか
  - `energy` = `score`（5段階）— 反応に使えるエネルギー
  - `approach` = `score`（5段階）— 利用者に引き寄せられるか遠ざかるか
  - `emit` = `noul` — そもそも反応するか
- 入力は日本語の短い状態記述 **8件**（デスクの相棒が反応する場面を想定）
- 道具: `docs/experiments/css-gesture/spike.py` / `run.sh` / `build_viewer.py` / `gestures.css`

## 結果

### 人が読めたか（1回目の判定）

`index.html`（θ=0.30 で焼き込み）を見せて判定してもらった結果:

- **`energy` の強弱は見た目で差が分かる** — 軸として機能している（④ は合格）
- **`waiting` / `late_night` / `branch_gone` は区別が難しい**。ただし「落ち込んでいたり
  元気が無いようなニュアンスは伝わる」

この3件は**ちょうど θ=0.30 で idle に落ちた3件**である。同じアニメーションなので区別できないのは
当然で、**ゲートが情報を捨てている**ことが人の目で確認された形。「元気が無い」が伝わるのは、
idle でも連続パラメータ（glow 0.036 / 0.122 / 0.180、speed、amp）が違うため。

### θ を下げると区別が回復する

| θ | 発火 | 内容 |
|---|---|---|
| 0.50 | 0/8 | 何も起きない（Clef の emit は最大 0.493） |
| 0.30 | 4/8 | fixed_bug, build_fail, approved, nag |
| 0.20 | 5/8 | + uncertain（flicker として復活） |
| **0.15** | **6/8** | **+ branch_gone（settle として復活）** |
| 0.10 | 7/8 | + late_night |
| 0.05 | 7/8 | 同じ（waiting の 0.036 が下限） |

**θ=0.15 で、指摘された3件のうち `branch_gone` が `settle` として復活し、`uncertain` も
`flicker` として残る。** 沈黙するのは `waiting`（emit 0.036）だけになる。
`waiting` と `late_night` はどちらも raw が `idle` なので、θ をいくら下げても**同じジェスチャー同士**で、
パラメータの差だけで区別することになる。

### `emit` は「感情の強さ」として読めた（nag の観察）

`nag`（同じ指摘を3回目、emit **0.493 で8件中最大**）について、
**「感情の強さ(哀)と縮小する動きで落ち込んでいるニュアンス、大泣きしているような風」** と読まれた。

重要なのは、**この時点でビューアが描いていたのは argmax のジェスチャー1つ**（`settle`）で、
確率の混合は表示していなかったこと。つまりこの読みは `settle` ＋ パラメータから来ている。
`nag` のパラメータは energy 1.04（低い）/ scale 0.94 / glow 0.493（最大）。

→ **`emit`（glow）はゲートである以前に「感情の強さ」として読める。** energy（体力の勢い）とは
別の軸として機能している。これは「ゲートで emit を捨てると情報が失われる」ことの、別方向からの裏づけ。

### 混合を重ね合わせで描くと「ぼやけた雲」になる

8ジェスチャーを確率に比例した不透明度で重ねるモードを実装して確認した（`index.html` の
「表示」セレクタで argmax と切替）。結果:

- **まとまった中間の動きにはならない。** 半透明の図形が少しずつずれて重なった雲のように見える
- 分布が1点に集中しているカード（`waiting` idle 83% / `uncertain` flicker 76%）は比較的まとまって見える
- 分散しているカードほど崩れる。`nag`（settle 30% / shake 21% / recoil 20%）が最も雲になる

→ **並行アニメーションの不透明度重ね合わせでは、確率の混合を動きの混合にできない。**
これは判断項目②（混合が意味のある中間になるか）への、否定的な実測結果。

### 姿勢パラメータ空間版を実装した（重ね合わせ → 補間）

上の雲の結果を受けて、語彙の持ち方そのものを変えた。

**設計**: ジェスチャーを `poses.json` に**姿勢パラメータ空間の点**として定義する。
次元は6つ:

| 次元 | 意味 |
|---|---|
| `amp_x` | 横方向の振れ幅（0-1） |
| `amp_y` | 縦方向の振れ幅（0-1） |
| `rise`  | 上下の静的な偏り。負 = 浮く / 正 = 沈む |
| `size`  | 体の大きさ（1.0 基準） |
| `freq`  | 動きの速さ（周期の逆数の相対値） |
| `flick` | 明滅の強さ（0-1） |

8ジェスチャーはこの空間の8点:

| gesture | amp_x | amp_y | rise | size | freq | flick |
|---|---|---|---|---|---|---|
| idle      | 0.00 | 0.28 |  0.00 | 1.00 | 1.00 | 0.00 |
| perk_up   | 0.00 | 0.95 | -0.55 | 1.10 | 1.70 | 0.00 |
| nod       | 0.00 | 0.70 |  0.15 | 0.96 | 1.45 | 0.00 |
| shake     | 0.90 | 0.00 |  0.00 | 1.00 | 1.65 | 0.00 |
| lean_in   | 0.00 | 0.42 | -0.45 | 1.24 | 0.75 | 0.00 |
| recoil    | 0.00 | 0.80 | -0.95 | 0.82 | 2.20 | 0.00 |
| settle    | 0.00 | 0.22 |  1.05 | 0.70 | 0.55 | 0.00 |
| flicker   | 0.00 | 0.06 |  0.00 | 1.00 | 1.10 | 1.00 |

**描画**: 常に1体。混合は**確率による姿勢ベクトルの重み付き平均（補間）**。
描画側（`gestures.css`）は8つの keyframe をやめ、`--p-*` 変数で駆動される
**往復の正弦1種類**になった。`nod` と `shake` は振れの軸（`amp_y` / `amp_x`）で分けているので、
混合すると**斜めの振れ**として素直に出る。

**実測（clef の8状態、θ=0.30、`mean` = 補間表示）**:

| key | top | ampx | ampy | rise | size | freq | flick |
|---|---|---|---|---|---|---|---|
| fixed_bug   | nod     | 0.01 | 0.66 | -0.10 | 1.01 | 1.37 | 0.03 |
| build_fail  | settle  | 0.05 | 0.31 | +0.49 | 0.83 | 0.92 | 0.09 |
| waiting     | idle    | 0.01 | 0.30 | +0.01 | 0.99 | 1.03 | 0.03 |
| branch_gone | settle  | 0.07 | 0.30 | +0.41 | 0.84 | 0.99 | 0.10 |
| uncertain   | flicker | 0.02 | 0.12 | +0.03 | 0.99 | 1.10 | 0.76 |
| late_night  | idle    | 0.04 | 0.34 | +0.24 | 0.93 | 1.03 | 0.06 |
| approved    | nod     | 0.00 | 0.66 | +0.09 | 0.98 | 1.40 | 0.01 |
| nag         | settle  | 0.18 | 0.36 | +0.11 | 0.88 | 1.30 | 0.07 |

`nag` の `amp_x 0.18` が**今回最大** — 内訳の `shake 21%` が横振れとして現れている。
`uncertain` の `flick 0.76` も突出。**分散した分布の成分が、雲ではなく姿勢の成分として出る。**

**検証（アニメーションを 0% で凍結して実測、`--dump-dom` と `getBoundingClientRect`）**:
- 変数は8カードすべてに適用されている
- 各枠は角丸四角**1つ**。雲状の多重像は無い（前版の症状は解消）
- **静止差は実在する**: 枠中心からのズレは **-15px（fixed_bug、浮く）〜 +6px（build_fail、沈む）**、
  体の高さは **34px（build_fail/branch_gone）〜 44px（fixed_bug）**。118px の枠に対して十分な差
- 注意: **スクリーンショットでは静止差が読めない。** 振動の途中を写すので、0% に凍結して
  `getBoundingClientRect` で測る必要がある（目視と vision は「揃っている」と誤読した）

**新たに生じた忠実度の損失**: 波の形を往復の正弦1種類に統一したので、
`perk_up` の「一瞬沈んでから跳ねる」や `nod` の「2回」のような**波形の違いは表現できない**。
振幅・速度・静的偏りで近似している。`fixed_bug`（nod 39% / perk_up 31% が拮抗）で最も目立つ。
波形カタログを増やせば戻せるが、そのぶん姿勢空間の次元が増える。

### `rise` を `lift` / `sink` に分割した（相殺の修正）

姿勢空間版を人の目で見た結果、**`fixed_bug` と `approved` の区別が難しい**と指摘された。
「意味が近いから問題ないのでは」という問いだったが、**原因は意味の近さではなく次元の設計**だった。

**実測（clef の8状態）**: `rise` は語彙の中で唯一「両側にジェスチャーがある」次元
（浮く側: recoil −0.95 / perk_up −0.55 / lean_in −0.45、沈む側: settle +1.05 / nod +0.15）。
符号付きの平均なので反対側同士が相殺する。

| 次元 | 相殺率（8状態平均） | 理由 |
|---|---|---|
| `rise` | **55%** | 両側にジェスチャーがある |
| `amp_x` | **0%** | `shake` だけが持つ |
| `flick` | **0%** | `flicker` だけが持つ |

| key | 浮く成分 | 沈む成分 | 相殺で消えた | 符号付き合計 |
|---|---|---|---|---|
| **nag** | 0.214 | 0.324 | **80%** | +0.110 |
| **fixed_bug** | 0.221 | 0.124 | **72%** | −0.098 |
| approved | 0.043 | 0.135 | 48% | +0.092 |
| build_fail | 0.097 | 0.585 | 28% | +0.488 |

**`fixed_bug` と `approved` が同じ姿勢になったのは、差がちょうど相殺される場所にあったため。**
相殺後の `rise` は −0.098 と +0.092 で、**符号が逆なのに絶対値がほぼ同じ**。
`nag` はさらに悪く、落ち込みが80%消えて相殺しない横振れだけが残っていた。

**原理**: 線形空間に符号付きの次元を置くと「沈む + 浮く = 中立」を仮定してしまう。
実際は「沈む + 浮く = 葛藤」。`nod`/`shake` で軸を分けたのと同じ解決を上下にも適用する。

**設計**: `rise` を非負の `lift` / `sink` に置換。各ジェスチャーは片方だけを立てる。
描画は:

- 静的な上下オフセット = `(sink − lift)` … 姿勢としての沈み／浮きを担う
- 縦の振れ幅に `+ 2*min(lift, sink)` を加算 … **符号付き平均が捨てる量そのもの**
  （`lift + sink − |sink − lift| = 2*min(lift, sink)`）なので、捨てていた情報を振れとして回復する

**単一ジェスチャー（片方だけ非ゼロ）では `min = 0` なので振れは増えない。**
つまり純粋な姿勢は旧版と完全に同一で、**混合のときだけ「葛藤が揺れとして見える」**。

**検証（アニメを 0% に凍結して `getBoundingClientRect` で実測）**:

| key | 縦振幅 旧 → 新 | 倍率 | 中心からのズレ |
|---|---|---|---|
| fixed_bug | 13.25 → **18.21** | 1.37x | −20 |
| approved | 12.28 → **13.89** | 1.13x | −12 |
| **nag** | 5.51 → **12.09** | **2.19x** | −9 |
| build_fail | 4.73 → 7.71 | 1.63x | +3 |
| branch_gone | 4.47 → 7.91 | 1.77x | +1 |

- **`fixed_bug` vs `approved` の縦振幅差が 1.08x → 1.31x**、中心ズレも −15/−11 → −20/−12 に分離
- **`nag` の縦振幅が 2.19x**（相殺で消えていた落ち込みの揺れが戻った）
- **単一ジェスチャーは不変**: argmax モードで葛藤項は 8/8 件すべて 0
- 副次的に、ほぼ純粋な分布（`waiting` = idle 83%）も末尾の lift/sink で 1.21x になる。
  葛藤の実量に比例するので想定内だが、**純粋な状態でも僅かに揺れる**ことは覚えておく

### Laya (0.42B) は判別しなかった

**8件すべてで `gesture = flicker`**、`emit` は 0.002〜0.112（すべて「反応しない」寄り）。

| state | gesture | top p | emit |
|---|---|---|---|
| fixed_bug | flicker | 0.533 | 0.054 |
| build_fail | flicker | 0.752 | 0.112 |
| waiting | flicker | 0.470 | 0.062 |
| branch_gone | flicker | 0.713 | 0.028 |
| uncertain | flicker | 0.304 | 0.035 |
| late_night | flicker | 0.881 | 0.002 |
| approved | flicker | 0.375 | 0.081 |
| nag | flicker | 0.285 | 0.101 |

確率は動いている（0.285〜0.881）のに、**argmax が定数**。日本語テキストの意味判断には
0.42B では足りない。**「速いから小さいモデル」はこの用途では成立しない。**

### Clef-Flash (9B) は判別した

| state | gesture | top p | conf | energy | approach | emit |
|---|---|---|---|---|---|---|
| fixed_bug（3日のバグが直った） | **nod** | 0.392 | 0.306 | 2.78 | 2.72 | 0.471 |
| build_fail（またビルドが落ちた） | **settle** | 0.548 | 0.483 | 1.06 | 1.09 | 0.356 |
| waiting（テストを待っている） | **idle** | 0.835 | 0.811 | 0.51 | 1.64 | **0.036** |
| branch_gone（ブランチを消された） | **settle** | 0.494 | 0.422 | 0.79 | 0.80 | 0.180 |
| uncertain（次に何をするか不明） | **flicker** | 0.760 | 0.726 | 0.93 | 1.15 | 0.223 |
| late_night（深夜3時） | **idle** | 0.421 | 0.338 | 0.79 | 1.74 | 0.122 |
| approved（レビュー全部OK） | **nod** | 0.831 | 0.807 | 2.22 | 2.91 | 0.435 |
| nag（同じ指摘を3回目） | **settle** | 0.296 | 0.195 | 1.04 | 0.64 | 0.493 |

**8件が5種類のジェスチャーに分かれ、energy / approach も意味の通る向きに出た。**
- 良い知らせ（fixed_bug, approved）で `nod`、energy が高く approach も高い（2.72 / 2.91 = 最も近づく）
- 悪い知らせ（build_fail, branch_gone, nag）で `settle`、energy と approach が低い
  （nag は approach 0.64 で最も遠ざかる）
- 迷い（uncertain）で `flicker`、待ち（waiting）で `idle` + emit 0.036（反応しない）
- `emit` は「反応すべき場面」で高く（0.435〜0.493）、「静かにしているべき場面」で低い（0.036〜0.122）

### θ = 0.5 では何も起きない（較正の実測）

`emit >= 0.5` を発火条件にすると、**8件すべてが idle になった**。Clef の `noul` は
最も明確な場面（nag 0.493）でも 0.5 に届かない。**しきい値は推測せずデータから決める必要がある。**

θ = 0.30 にすると 4件が発火し、`waiting`（raw=idle）と `late_night`（raw=idle）は正しく沈黙する。

## 結論

- **路線としては成立する。** 決定モデルは「どれを・どれくらい」を判別でき、決定論的な写像で
  CSS の動きに落とせる。決定モデルに CSS を生成させる必要は無い（できない）
- **モデル選択が決定的。** Laya (0.42B) は argmax が定数になり使えない。Clef (9B) は判別する。
  「質問が独立に評価される（Laya）」「速い（0.016s）」という利点は、判別できないなら意味が無い
- **`noul` のしきい値はデータから決める。** θ=0.5 は素直だが全部沈黙した
- **設計上のひっかかりを1つ見つけた**: θ でゲートすると `uncertain → flicker` が idle に落ちる。
  **迷いのジェスチャーは本質的に emit が低い**ので、ゲートは「迷いを表現する手段」を真っ先に殺す。
  人の判定でも、ゲートで idle に落ちた状態どうしが区別できないと指摘された（これは当然の結果で、
  ゲートが情報を捨てていることの実測）。**θ=0.15 まで下げると区別が回復する**
- **`energy` 軸は人が読める。** 動きの速さ（0.94〜1.44s）と振幅（0.59〜1.23）の差は知覚できる。
  vmc-pet が「数値的には差があるが目で分かるかは怪しい」で詰まったのと同じ罠を心配していたが、
  この軸については問題にならなかった
- **`emit` は「感情の強さ」として読める。** `nag`（emit 0.493 で最大）が「感情の強さ(哀)と縮小する動きで
  大泣きしているよう」と読まれた。energy（体力の勢い）とは別の軸。よって
  **ゲートで emit を捨てるのは、感情の強さの情報を捨てることでもある**
- **混合は「重ね合わせ」では作れず、「補間」なら作れる。** 不透明度で重ねると雲になる（実測）。
  語彙を**姿勢パラメータ空間の点**に変え、混合を**重み付き平均**にして1体で描く方式に切り替えたところ、
  雲は解消し、分散した分布の成分が姿勢の成分として出た（`nag` の `amp_x 0.18` は `shake 21%` の寄与）。
  **これで vmc-pet の「状態がそのまま見た目になる」と同じ構造になった**
- **符号付きの次元は混合で壊れる。** `rise`（上下）を1本の符号付き次元にしていたため、
  反対側のジェスチャー同士が相殺し、8状態平均で**55%が消えていた**（`nag` は80%）。
  **非負の2チャネル（`lift`/`sink`）に割り、捨てていた量 `2*min(lift, sink)` を縦の振れとして
  戻す**ことで回復した（`nag` の縦振幅 2.19x、`fixed_bug` vs `approved` の差 1.08x→1.31x）。
  片側にしかジェスチャーが無い次元（`amp_x`/`flick`）は相殺率 0% で無傷だった
- **代償は波の形。** 正弦1種類に統一したので `perk_up` の「沈んでから跳ねる」等は失われた。
  姿勢空間の次元を増やせば戻せるが、**表現力と解像度のトレードオフは消えない**
- **目視確認には限界がある。** 静止差は −15px〜+6px と実在するが、スクリーンショットでは
  振動の途中が写るので読めない。**アニメを 0% に凍結して `getBoundingClientRect` で測る**のが正しい

## 限界

- **人が読み分けられるかの判定は部分的。** 分かったのは「`energy` の強弱は読める」
  「`emit` は感情の強さとして読める」「重ね合わせの混合は雲になる」の3点。**残りは未判定**:
  8個のジェスチャー個々の混同しやすさ（`nod`/`perk_up`、`settle`/`recoil` など）、
  補間した姿勢が「伝わる中間」になるか、`confidence` が低いときの見え方
- **補間した姿勢が「意味のある中間」として読めるかは未判定。** 雲にはならないことは確認したが、
  それは「壊れていない」ことの確認で、「伝わる」ことの確認ではない。`nag`（conf 0.20）のように
  **最も強く発火しているのに最も曖昧な姿勢**になる例がある。ビューアで動きを見て判定が必要
- **波の形の忠実度が落ちた。** 正弦1種類に統一したので `perk_up` の「一瞬沈んでから跳ねる」や
  `nod` の「2回」は表現できない。`fixed_bug`（nod 39% / perk_up 31%）で最も目立つ
- **8個のジェスチャー個々の混同しやすさは未判定。** `nod`/`perk_up`、`settle`/`recoil` など
- 状態は 8件だけ。日本語のみ（英語での挙動は未確認）
- `score` のレベル刻みは 5 段階だけ。2〜10 の範囲で刻みを変えたときの挙動は未確認
- レイテンシは CPU のみ。GPU での再測は未実施
- Clef は質問を jointly に判断するため、`gesture` と `energy` を同時に聞いたことによる
  相互作用の大きさは未測定（Laya は独立だが判別しなかったので比較できない）
- サンプリング（確率比例でジェスチャーを選ぶ）は試していない。argmax のみ
- decay を使った事後分布の積分（持続状態）は未実装
